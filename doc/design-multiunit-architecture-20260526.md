## Problem Statement

TTA 표준화본부 산하 4개 단(표준기획단·표준혁신단·AI융합표준단·전파네트워크표준단)이 각자 다른 관심 도메인을 가지고 있으나, 현재 AI 뉴스 인텔리전스 시스템은 단일 설정(키워드·RSS·이메일수신자)만 지원한다. 이로 인해:
- 단별 맞춤 뉴스 수집이 불가
- 4명의 단 담당자가 각자 설정을 관리할 수 없음
- 최상위 관리자(본부장급)가 전체 운영을 모두 직접 해야 함

목표: 최상위 관리자는 전역 시스템 설정(API 키 등)을 관리하고, 4명의 단 담당자는 각자의 RSS·키워드·이메일수신자를 독립적으로 관리하는 멀티유닛 시스템 구축.

## Confirmed Premises (검증된 전제)

1. ✅ 4개 단이 각자 다른 Google Alerts RSS + 네이버 키워드를 운영한다  
2. ✅ Google Workspace OAuth(@tta.or.kr)로 4명 인증 — 이미 구현된 기반 사용  
3. ✅ 각 단이 독립적으로 수집·분석을 실행한다 (공유 수집 X, 단별 수집 O)  
4. ✅ **(수정됨)** 단 담당자는 자기 단만 편집 가능, 다른 단의 RSS·키워드는 읽기 전용으로 볼 수 있음. 단, 이메일 수신자는 관리자만 조회 가능 (투명성 O, 수신자 목록 제외)  
5. ✅ 홈 대시보드 상단 탭에서 모든 사용자가 4개 단의 일일 분석 리스트를 볼 수 있음  
6. ✅ 동향 분석 메뉴는 4개 단 데이터 통합 RAG 검색 (전체 누적 데이터 대상)

## Recommended Approach: B — Units Table Architecture

### DB 변경

**⚠️ SQLite/PostgreSQL 분기 필요** — `check_and_migrate_database()`의 기존 `is_pg` 패턴 그대로 적용.

```python
# check_and_migrate_database() 내 추가 (is_pg 분기 활용)
id_col = "id SERIAL PRIMARY KEY" if is_pg else "id INTEGER PRIMARY KEY AUTOINCREMENT"

# units 테이블 생성
conn.execute(text(f"""
    CREATE TABLE IF NOT EXISTS units (
        {id_col},
        name VARCHAR(50) UNIQUE NOT NULL,
        display_name VARCHAR(100) NOT NULL,
        description TEXT,
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
    )
"""))

# PostgreSQL: INSERT OR IGNORE → INSERT ... ON CONFLICT DO NOTHING
if is_pg:
    conn.execute(text("""
        INSERT INTO units (name, display_name) VALUES
            ('standards_planning', '표준기획단'),
            ('standards_innovation', '표준혁신단'),
            ('ai_convergence', 'AI융합표준단'),
            ('radio_network', '전파네트워크표준단')
        ON CONFLICT (name) DO NOTHING
    """))
else:
    conn.execute(text("""
        INSERT OR IGNORE INTO units (name, display_name) VALUES
            ('standards_planning', '표준기획단'),
            ('standards_innovation', '표준혁신단'),
            ('ai_convergence', 'AI융합표준단'),
            ('radio_network', '전파네트워크표준단')
    """))
```

**컬럼 추가 (기존 ALTER TABLE 패턴 사용):**
- `user_settings`: `unit_id INTEGER` (FK to units.id), `google_alerts_rss TEXT DEFAULT '[]'`
- `news_articles`: `unit_id INTEGER` (FK to units.id), NULL = 마이그레이션 이전 수집 기사

**🔧 save_user_settings() 수정 주의**: `unit_id`, `google_alerts_rss` 추가 시 SQLite upsert와 PostgreSQL upsert **각각 2곳씩, 총 4곳 수정** — (1) INSERT 컬럼 목록과 VALUES 절, (2) ON CONFLICT DO UPDATE SET 절. `load_user_settings()`는 SELECT 절 1곳 수정.

**기존 데이터 처리 정책**: `news_articles.unit_id = NULL` 인 기존 기사는 홈 탭의 "전체" 보기에만 포함, 각 단 탭에는 표시 안 함. RAG 검색에서 단 필터 선택 시 NULL 기사 제외, "전체" 선택 시 포함. 별도 backfill 스크립트 불필요.

#### 동향 분석 (📈 동향 분석) — 통합 RAG
```
[단 필터: 전체 | 표준기획단 | 표준혁신단 | AI융합표준단 | 전파네트워크표준단]
  단 필터는 RAG 검색창에만 적용
[검색창: 자연어로 질문 입력 → GPT-4o 기반 RAG 답변]

[연속 등장 이슈 | 표준화 갭 현황] ← 기존 탭 유지, 이번 설계 범위 외
  ※ 단 필터 영향 없음, 전체 데이터 기준 동작 유지
```

**RAG 단 필터 구현 방식** (`rag_search.py`의 `answer_with_rag()` 수정):
- 단 필터는 **SQL pre-filter** 방식: 벡터 임베딩 유사도 검색 전, 임베딩 저장 테이블에서 `unit_id` 조건으로 후보 기사를 먼저 필터링
- "전체" 선택 시: unit_id 필터 없음 (NULL 포함 전체 대상)
- "표준기획단" 선택 시: `WHERE unit_id = 해당_id` 조건으로 코사인 유사도 대상 축소
- 임베딩 단계(`embed_unprocessed_articles()`) 자체는 변경 없음 — 기사 임베딩 시 unit_id 컨텍스트 불필요

**⚠️ `st.experimental_user` 버전 주의**: Streamlit 1.31에서 `st.user`로 이전. 배포 환경 버전 확인 필요. ≥ 1.31이면 `st.experimental_user` → `st.user` 전체 교체 후 단 인증 흐름 구현 시작.

**⚠️ SQLite FK**: SQLite는 기본적으로 FK 제약 미적용 (`PRAGMA foreign_keys = OFF`). `unit_id`는 soft reference로 운영 — 애플리케이션 레벨에서 고아 참조 방지 (단 삭제 기능 없음, units 테이블은 4개 고정).

**기간 필터 ("최근 1주 / 1개월 / 3개월")**: 이번 설계 범위 외 — 차후 별도 구현.

**관리자 단 멤버십 UI — 현재 담당자 표시**:
현재 담당자 이메일은 역방향 조회로 표시:
```sql
SELECT user_email FROM user_settings WHERE unit_id = ? LIMIT 1
-- 결과 없으면 '미배정' 표시
```

**신규 함수 `load_unit_settings(unit_id: int) → dict`**:
```python
def load_unit_settings(unit_id: int) -> dict:
    """units.id로 해당 단 담당자의 user_settings 로드.
    담당자가 없거나 설정 없으면 빈 값(기본값) 반환."""
    with get_db_session() as session:
        row = session.execute(
            sa_text("SELECT keywords, google_alerts_rss FROM user_settings "
                    "WHERE unit_id = :uid LIMIT 1"),
            {"uid": unit_id}
        ).fetchone()
    if row is None:
        return {'keywords': '[]', 'google_alerts_rss': '[]'}  # 빈 설정, 에러 아님
    return {'keywords': row[0] or '[]', 'google_alerts_rss': row[1] or '[]'}
```

**신규 함수 `run_unit_collection(unit_id: int)`**:
```python
def run_unit_collection(unit_id: int):
    """특정 단의 RSS/키워드로 뉴스 수집 후 news_articles.unit_id 태깅"""
    unit_settings = load_unit_settings(unit_id)
    rss_urls = json.loads(unit_settings['google_alerts_rss']) or DEFAULT_RSS
    naver_queries = json.loads(unit_settings['keywords']) or DEFAULT_QUERIES

    # get_news_data()에 unit_id 신규 파라미터 추가 (기본값 None — 하위 호환)
    articles = get_news_data(rss_urls=rss_urls, naver_queries=naver_queries, unit_id=unit_id)
    # save_news_to_db()에 unit_id 신규 파라미터 추가 (기본값 None — 하위 호환)
    save_news_to_db(articles, unit_id=unit_id)
```

**`get_news_data()`/`save_news_to_db()` 변경 범위**:
- `unit_id=None` 기본값 추가 → 기존 호출부 수정 불필요 (하위 호환)
- `unit_id`가 None이 아닐 때만 `news_articles.unit_id` 태깅

**`get_all_user_keywords()` 변경 범위**:
- `unit_id=None` 파라미터 추가
- `unit_id`가 None이면 기존 동작 유지 (전체 사용자 키워드 합집합 — 리포트/키워드 클라우드용)
- `unit_id`가 지정되면 해당 단 담당자 키워드만 반환

**CLI `--unit` 파싱**:
```python
# news_engine.py main() — argparse 추가
parser.add_argument('--unit', type=str, default=None,
                    help='단 name (units.name): standards_planning, standards_innovation, ...')

# 실행 시 unit_id 조회
if args.unit:
    row = session.execute(sa_text("SELECT id FROM units WHERE name=:n"), {"n": args.unit}).fetchone()
    if row is None:
        sys.exit(f"ERROR: --unit '{args.unit}' 을 units 테이블에서 찾을 수 없습니다.")
    unit_id = row[0]
    run_unit_collection(unit_id)
else:
    run_daily_collection()  # 기존 전체 수집 (unit_id=None)
```

**주간/월간 리포트 범위**: 이번 설계 범위 외 — weekly/monthly 실행은 기존 단일 동작 유지. 단별 주간 리포트는 차후 별도 설계.

**GitHub Actions 타임아웃 계획**: 현재 단일 수집 런타임 측정 후 결정. 단일 수집이 8분 이내면 4단 순차 실행 총 32분 → job timeout 60분으로 설정. 단일 수집이 8분 초과이면 4개 parallel job(각각 독립 실행, write conflict 없음 — unit_id 분리)으로 전환.

## Distribution Plan

- 기존 Streamlit Cloud 배포 파이프라인 유지
- **GitHub Actions**: `daily-collection.yml`에 4개 단 수집 step 순차 추가 (job timeout 60분으로 설정):
  ```yaml
  - run: python news_engine.py daily --unit standards_planning
  - run: python news_engine.py daily --unit standards_innovation
  - run: python news_engine.py daily --unit ai_convergence
  - run: python news_engine.py daily --unit radio_network
  ```
  단일 수집 런타임이 8분 초과인 경우 4개 parallel job으로 전환 가능 (unit_id가 분리돼 write conflict 없음)
- **DB 마이그레이션**: 자동 (앱 시작 시 `check_and_migrate_database()` 실행)
- **단↔이메일 매핑의 단일 진실 소스**: `units` 테이블 + `user_settings.unit_id` FK — Streamlit secrets에 단 매핑 정보 저장하지 않음 (API 키만 secrets에 보관)

## Reviewer Concerns (미해결 — 구현 전 확인 필요)

3회 adversarial review 후 남은 이슈:

### ⚠️ HIGH — 구현 차단 가능
1. **RAG 임베딩 테이블 `unit_id` 연결 방식 미명시**  
   `article_embeddings` 테이블에 `unit_id` 컬럼을 추가할지, 아니면 `news_articles`와 JOIN할지 결정 필요. `search_similar_articles()` 함수의 WHERE 절 수정 범위도 확정 전.  
   → **구현 전 `rag_search.py` 스키마 확인 후 확정**

2. **미로그인 신규 담당자 멤버십 배정 불가 버그**  
   관리자가 `user_settings.unit_id`를 배정하려면 해당 사용자가 최소 1회 로그인해야 레코드 존재. 최초 배정 시 행 없으면 INSERT 필요.  
   → **멤버십 배정 UI에서 upsert(없으면 INSERT) 처리 추가**

### ⚠️ MEDIUM — 구현 중 결정 필요
3. **`get_all_user_keywords()` 실제 함수명 확인 필요** — `news_engine.py:3427` 함수명 재확인  
4. **`st.experimental_user` → `st.user` 교체가 선행 조건** — 현재 Streamlit 1.50.0. 0단계로 전체 교체 후 구현 시작  
5. **홈 탭 "전체" 탭 추가 여부 결정** — NULL unit_id 기존 기사를 별도 "전체" 탭으로 노출할지, 아니면 숨길지  
6. **SQLite WAL 모드 적용 여부** — GitHub Actions 수집 중 앱 동시 접근 시 쓰기 경합. `PRAGMA journal_mode=WAL` 적용 결정 필요
