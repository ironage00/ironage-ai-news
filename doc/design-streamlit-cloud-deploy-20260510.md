## 전제 (설계 결정의 근거)

1. **Supabase(PostgreSQL) 필수** — Streamlit Cloud의 파일시스템은 재시작 시 초기화됨. SQLite는 사용 불가. Supabase 무료 플랜: 500MB DB, 충분.
2. **GitHub Actions 스케줄러** — Streamlit Cloud는 백그라운드 작업 불가. GitHub Actions cron이 daily/weekly 수집·분석 트리거.
3. **API 키 공유 방식** — TTA 내부 서비스이므로 모든 API 키(OpenAI/Gemini/Claude 등)는 관리자가 GitHub Secrets + Streamlit Secrets에 저장. 사용자별 API 키 입력 불필요.
4. **단일 DB, 키워드 기반 필터** — Approach A에서는 완전한 팀별 데이터 격리 없음. 사용자가 설정한 키워드로 관련 뉴스를 필터링해서 보여줌.
5. **인증: Google OAuth (@tta.or.kr 도메인 제한)** — TTA 전 직원이 이미 사용하는 Google Workspace 계정을 그대로 사용. 별도 비밀번호 관리 불필요. `streamlit-authenticator` 패키지 및 `auth_config.yaml` 불필요.
6. **Google Docs: 서비스 계정(Service Account)** — TTA Google Cloud 조직에서 서비스 계정 발급. OAuth2 `token.json`의 90일 만료 문제 없음. GitHub Actions에서 headless 영구 실행 가능.

## 필요한 변경 사항

### 1. DB 연결 (news_engine.py)

현재 코드는 SQLAlchemy + SQLite. PostgreSQL은 URL만 바꾸면 SQLAlchemy가 처리함.

**`news_engine.py` — `get_db_session()` 근처:**
```python
# 현재
DB_PATH = os.path.join(DATA_DIR, 'news.db')
DB_URL = f"sqlite:///{DB_PATH}"

# 변경: 환경변수 우선, 없으면 SQLite 폴백
DB_URL = os.environ.get('DATABASE_URL') or f"sqlite:///{DB_PATH}"
# Supabase는 postgresql:// 대신 postgresql+psycopg2:// 필요
if DB_URL.startswith('postgresql://'):
    DB_URL = DB_URL.replace('postgresql://', 'postgresql+psycopg2://', 1)
```

**주의:** SQLite에만 있는 함수(예: `PRAGMA`, `JSON_EXTRACT`)는 PostgreSQL에서 달라짐. 코드 전체 grep 필요:
```bash
grep -n "PRAGMA\|JSON_EXTRACT\|sqlite" news_engine.py
```

**DB 헬퍼 함수 (main_app.py 또는 news_engine.py에 추가):**

```python
def load_user_settings(user_email: str) -> dict:
    with get_db_session() as session:
        row = session.execute(
            "SELECT keywords, ai_model, email_recipients, schedule_daily, schedule_weekly "
            "FROM user_settings WHERE user_email = :email",
            {"email": user_email}
        ).fetchone()
    if row is None:
        return {}
    return {
        'keywords': json.loads(row.keywords or '[]'),
        'ai_model': row.ai_model or 'gemini',
        'email_recipients': json.loads(row.email_recipients or '[]'),
        'schedule_daily': row.schedule_daily,
        'schedule_weekly': row.schedule_weekly,
    }

def save_user_settings(user_email: str, settings: dict):
    with get_db_session() as session:
        session.execute("""
            INSERT INTO user_settings (user_email, keywords, ai_model, email_recipients,
                schedule_daily, schedule_weekly, updated_at)
            VALUES (:email, :kw, :model, :emails, :daily, :weekly, CURRENT_TIMESTAMP)
            ON CONFLICT (user_email) DO UPDATE SET
                keywords=EXCLUDED.keywords,
                ai_model=EXCLUDED.ai_model,
                email_recipients=EXCLUDED.email_recipients,
                schedule_daily=EXCLUDED.schedule_daily,
                schedule_weekly=EXCLUDED.schedule_weekly,
                updated_at=EXCLUDED.updated_at
        """, {
            "email": user_email,
            "kw": json.dumps(settings['keywords'], ensure_ascii=False),
            "model": settings['ai_model'],
            "emails": json.dumps(settings['email_recipients'], ensure_ascii=False),
            "daily": settings['schedule_daily'],
            "weekly": settings['schedule_weekly'],
        })
```

### 5. Google Docs — 서비스 계정(Service Account) 전환

기존 `credentials.json` + `token.json` 방식은 90일 후 토큰 만료 → GitHub Actions headless 환경에서 재인증 불가.

**서비스 계정 발급 절차 (1회):**
```
1. Google Cloud Console (console.cloud.google.com)
   → TTA Workspace 계정(@tta.or.kr)으로 로그인
   → 프로젝트 선택 (기존 프로젝트 또는 신규 생성)

2. IAM & Admin → Service Accounts → "서비스 계정 만들기"
   → 이름: ironage-docs-writer
   → 역할: 없음 (역할 없이 생성)
   → "키 만들기" → JSON → 다운로드 (ironage-sa.json)

3. Google Drive에서 보고서 저장 폴더를 서비스 계정 이메일에 공유
   (ironage-docs-writer@[project].iam.gserviceaccount.com — 편집자 권한)

4. Google Docs API 활성화
   → APIs & Services → Library → "Google Docs API" 활성화
   → "Google Drive API" 활성화
```

**`news_engine.py` — Docs 인증 부분 변경:**
```python
# 기존 (OAuth2 방식 — 90일 만료)
from google_auth_oauthlib.flow import InstalledAppFlow
creds = flow.run_local_server(...)

# 변경 (서비스 계정 방식 — 만료 없음)
import json, os
from google.oauth2 import service_account
from googleapiclient.discovery import build

def _get_docs_service():
    sa_json = os.environ.get('GOOGLE_SERVICE_ACCOUNT_JSON')
    if sa_json:
        info = json.loads(sa_json)
    else:
        with open('ironage-sa.json') as f:
            info = json.load(f)
    creds = service_account.Credentials.from_service_account_info(
        info,
        scopes=['https://www.googleapis.com/auth/documents',
                'https://www.googleapis.com/auth/drive']
    )
    return build('docs', 'v1', credentials=creds)
```

## 데이터베이스 마이그레이션 계획

기존 `data/news.db` 데이터를 Supabase로 이전:

```python
# migrate_sqlite_to_postgres.py (1회용 스크립트)
import sqlite3, psycopg2, json, os

src = sqlite3.connect('data/news.db')
dst = psycopg2.connect(os.environ['DATABASE_URL'])

# news_articles 테이블 이전
rows = src.execute("SELECT * FROM news_articles").fetchall()
cols = [d[0] for d in src.execute("SELECT * FROM news_articles").description]

with dst.cursor() as cur:
    for row in rows:
        placeholders = ', '.join(['%s'] * len(cols))
        cur.execute(
            f"INSERT INTO news_articles ({', '.join(cols)}) VALUES ({placeholders}) "
            f"ON CONFLICT (link) DO NOTHING",
            row
        )
dst.commit()
print(f"{len(rows)}개 기사 이전 완료")
```

## 열린 문제

1. **multi-user 이메일 발송**: 현재 `run_weekly_report()`는 `config.gmail_receivers` 단일 목록 사용. 팀별 발송을 위해 `user_settings`에서 수신자를 조회하는 로직 추가 필요. `run_weekly_report(receivers_override=list)`처럼 파라미터를 받도록 시그니처 수정 검토.

4. **Gmail 앱 비밀번호 (@tta.or.kr Workspace)**: Google Workspace에서 앱 비밀번호 사용을 허용하려면 Google Workspace 관리자가 "2단계 인증 + 앱 비밀번호 허용" 설정을 켜야 함. 관리자 확인 필요.
