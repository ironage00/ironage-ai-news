## DB 스키마 (news_articles)

```sql
CREATE TABLE news_articles (
    id            SERIAL PRIMARY KEY,
    title         TEXT NOT NULL,
    link          TEXT UNIQUE,           -- 중복 방지 기준
    source        TEXT,                  -- 뉴스 소스명
    published     TEXT,                  -- 발행 날짜 (문자열)
    collected_at  TIMESTAMP WITH TIME ZONE DEFAULT NOW(),  -- UTC 저장
    content       TEXT,                  -- 기사 본문 (요약)
    quality_score FLOAT,                 -- AI 품질 점수 (0~1)
    is_selected   BOOLEAN DEFAULT FALSE, -- 선별 여부
    is_analyzed   BOOLEAN DEFAULT FALSE, -- AI 분석 완료 여부
    analysis_result TEXT,                -- AI 분석 결과 (JSON)
    ai_model      TEXT,                  -- 분석에 사용한 AI 모델
    extracted_keywords TEXT,             -- 추출된 키워드 목록
    unit_id       TEXT,                  -- 귀속 단(팀) ID
    embedding     VECTOR(1536)           -- OpenAI 임베딩 벡터 (RAG용)
);
```

자동 마이그레이션: `check_and_migrate_database()`가 시작 시 스키마를 확인하고  
누락 컬럼을 자동으로 추가합니다.

## 데이터 흐름 상세

### Phase 1: 뉴스 수집 (`get_news_data()`)

```
① Google Alerts RSS 파싱 (feedparser)
   └── 각 RSS URL에서 entry 목록 수집
   
② 네이버 뉴스 API 호출
   └── naver_queries의 각 키워드로 검색 API 호출
   └── JSON 응답에서 기사 목록 추출

③ 표준화 기관 RSS 파싱
   └── ITU, ISO 등 공식 기관 RSS

④ 중복 제거 (deduplicate_news())
   └── URL 완전 일치
   └── 제목 Jaccard 유사도 (임계값 초과 시 중복 처리)
```

### Phase 2: AI 품질 필터링 (`filter_news_by_ai()`)

```
① 3단계 ICT 관련도 필터
   ├── 강한 ICT 마커 → 즉시 통과
   ├── 비ICT 패턴 → 즉시 제외 (IT와 무관한 일반 뉴스)
   └── AI 컨텍스트 마커 → 통과

② GPT-4o 품질 점수화
   └── 각 기사의 ICT/표준화 관련도를 0~1 점수로 평가
   └── 상위 20% 선별 (quality_score > 임계값)
```

### Phase 3: DB 저장 (`save_news_to_db()`)

```
① 24시간 이내 중복 URL 체크 (DB 조회)
② 단별 키워드 매칭으로 unit_id 자동 배정
③ SQLAlchemy ORM으로 Supabase(PostgreSQL)에 UPSERT
```

### Phase 4: AI 심층 분석 (`analyze_news_with_ai()`)

```
① is_analyzed=False인 기사 조회
② ThreadPoolExecutor로 병렬 처리
③ GPT-4o 또는 Claude로:
   ├── 200자 이내 요약
   ├── 핵심 키워드 5개
   ├── 표준화 시사점
   └── 중요도 등급 (HIGH/MEDIUM/LOW)
④ 결과를 analysis_result(JSON)로 저장
⑤ is_analyzed = True 업데이트
```

### Phase 5: 리포트 생성 및 발송

```
① trend_analyzer.py
   └── 단별 분석 결과 취합
   └── Google Docs API로 문서 생성
   └── Gmail SMTP로 HTML 이메일 발송

② auto_intel_report.py (급등 감지 시)
   └── 엔티티 급등 감지
   └── RAG 검색으로 관련 기사 수집
   └── AI 내러티브 생성
   └── 보고서 추가 + 발송
```

## Phase 4 파이프라인 상태 기계

`auto_intel_report.py`는 7개 노드로 구성된 파이프라인입니다.

```
node_load_data
    │
    ▼
node_detect_surges ─── 급등 없으면 ─▶ node_build_report ──▶ node_send_report
    │
    ▼ (급등 감지 시)
node_rag_retrieve
    │
    ▼
node_gen_narrative
    │
    ▼
node_build_report
    │
    ▼
node_append_to_doc
    │
    ▼
node_send_report (skip_email=True이면 건너뜀)
```

각 노드 오류는 `state['errors']`에 누적되며,  
치명적 오류 발생 시 후속 노드가 중단됩니다.

## RAG 검색 구조 (rag_search.py)

```
사용자 질문
    │
    ▼
OpenAI text-embedding-3-small으로 질문 벡터화 (1536차원)
    │
    ▼
Supabase에서 코사인 유사도 상위 기사 검색
    │
    ▼
키워드 매칭 검색 결과와 결합 (하이브리드)
    │
    ▼
관련 기사 컨텍스트로 GPT-4o 답변 생성
    │
    ▼
답변 + 참조 기사 목록 반환
```

## 중요 상수 (news_engine.py 상단)

```python
OPENAI_MODEL_DEFAULT      = "gpt-4o"
CLAUDE_MODEL_DEFAULT      = "claude-sonnet-4-6"
GEMINI_MODEL_DEFAULT      = "gemini-2.5-flash"
PERPLEXITY_MODEL_DEFAULT  = "sonar-pro"

EMBED_MODEL               = "text-embedding-3-small"
EMBED_BATCH_SIZE          = 200       # 임베딩 배치 크기

JACCARD_THRESHOLD_NUMERIC = 0.7       # 제목 중복 판정 임계값
JACCARD_THRESHOLD_TEXT    = 0.6

ICT_QUALITY_THRESHOLD     = 0.4       # AI 품질 점수 하한
TOP_ARTICLE_RATIO         = 0.2       # 상위 20% 선별
```

모델명 변경 시 이 상수만 수정하면 전체에 적용됩니다.

## 시간대 처리 규칙

| 상황 | 사용 시간대 | 이유 |
|------|-----------|------|
| DB 저장 (`collected_at`) | UTC | DB 저장 표준 |
| 표시·파일명·로그 | KST | 사용자 가독성 |
| 오늘 기사 집계 기준 | KST 자정 | 업무일 기준 |
| RSS 피드 날짜 비교 | UTC | RFC 2822 기준 |

KST 처리: `_KST_TZ = pytz.timezone('Asia/Seoul')` / `_now_kst()` 헬퍼 사용.
