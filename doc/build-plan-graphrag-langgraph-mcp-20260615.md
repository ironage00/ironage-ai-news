## 전략 선택: 가치 우선 순서 (B안)

사용자가 원안(MCP → LangGraph → GraphRAG)이 아닌 **B안(GraphRAG → LangGraph → MCP)**을 선택.

**근거**: MCP로 먼저 노출하기보다, 검색 품질을 먼저 올린 뒤 MCP 툴의 품질이 강화된 상태에서 노출하는 것이 사용자 경험상 더 가치 있음.

## Phase 1: GraphRAG — 그래프 강화 RAG 검색

### 목표
뉴스 기사를 벡터 유사도로만 검색하는 현재 RAG를 **엔티티 관계 그래프**로 보강.  
"5G와 삼성의 관계"처럼 **복수 엔티티 간 관계를 추적하는 질문**에 답할 수 있게 됨.

### 현재 vs 목표

```
현재:
  자연어 쿼리 → 벡터 유사도 검색 → GPT-4o 답변

목표 (GraphRAG):
  자연어 쿼리
    ↓ 엔티티 추출 (GPT-4o)
    ↓
  ┌─ 벡터 유사도 검색 (rag_search.py) — 기사 풀 확보
  └─ 그래프 서브그래프 탐색 (knowledge_graph.py) — 관계 컨텍스트 추가
    ↓
  통합 컨텍스트 → GPT-4o 답변 (기사 + 관계 설명 포함)
```

### 구현 세부 사항

#### `answer_with_rag()` 반환 계약 (rag_search.py:439)

{

    'sources': list, # 참조 기사 목록 (각 항목: id, title, link, source 포함)
    'query': str,    # 원본 쿼리 (echo-back)
}

`answer_with_graph_rag()`은 이 스펙에 `graph_context`, `entities_found` 두 키를 **추가**한다.  
기존 키는 변경하지 않아 `main_app.py` 호환 유지.

#### 신규 파일: `graph_rag.py`

```python
"""
GraphRAG 통합 모듈
rag_search.py (벡터 검색) + knowledge_graph.py (그래프) 쿼리 시점 연결
"""
from typing import Dict, List, Optional
import json

from rag_search import answer_with_rag
from knowledge_graph import build_entity_graph
from news_engine import get_openai_client, OPENAI_MODEL_DEFAULT, load_news_from_db, log_info


def extract_query_entities(query: str, client) -> List[str]:
    """쿼리에서 핵심 엔티티 추출 (기업·기술·국가명)."""
    resp = client.chat.completions.create(
        model=OPENAI_MODEL_DEFAULT,
        messages=[{
            "role": "user",
            "content": (
                f"다음 질문에서 핵심 기업명·기술명·국가명을 최대 3개 추출하세요.\n"
                f"JSON 배열로만 출력: [\"엔티티1\", \"엔티티2\"]\n\n질문: {query}"
            )
        }],
        max_tokens=100,
        temperature=0.0
    )
    text = resp.choices[0].message.content.strip()
    try:
        return json.loads(text)
    except Exception:
        return []


def get_graph_context(entities: List[str], G, max_hops: int = 2) -> str:
    """엔티티 목록에서 그래프 서브그래프 컨텍스트 생성."""
    if not entities or G is None or G.number_of_nodes() == 0:
        return ""

    context_lines = []
    for entity in entities:
        # 1-hop 이웃 노드 탐색
        neighbors = []
        for node in G.nodes():
            # 부분 문자열 매칭 (근사적) — "삼성" → "삼성전자" 매칭됨
            # 오탐이 많으면 Phase 2에서 fuzzywuzzy.fuzz.token_set_ratio() 교체 고려
            if entity.lower() in node.lower():
                for nbr in G.neighbors(node):
                    weight = G.edges[node, nbr].get('weight', 1)
                    neighbors.append((nbr, weight))
        if neighbors:
            neighbors.sort(key=lambda x: x[1], reverse=True)
            top = neighbors[:5]
            rel_str = ", ".join([f"{n}({w}회)" for n, w in top])
            context_lines.append(f"- {entity}와 함께 언급된 주요 엔티티: {rel_str}")

    return "\n".join(context_lines) if context_lines else ""


def answer_with_graph_rag(
    query: str,
    days: int = 30,
    unit_id: Optional[int] = None,
    max_articles: int = 5,
) -> Dict:
    """
    GraphRAG 답변 생성.
    벡터 검색 + 그래프 관계 컨텍스트를 통합해 GPT-4o에 전달.

    Returns:
        {
            'answer': str,
            'sources': list,
            'graph_context': str,  # 추가된 그래프 관계 정보
            'entities_found': list,
        }
    """
    client = get_openai_client()

    # Step 1: 쿼리 엔티티 추출
    entities = extract_query_entities(query, client)
    log_info(f"[GraphRAG] 추출된 엔티티: {entities}")

    # Step 2: 기존 RAG로 기사 검색 (변경 없음 — 하위 호환)
    rag_result = answer_with_rag(query=query, days=days, unit_id=unit_id)

    # Step 3: 지식 그래프에서 관계 컨텍스트 추가
    graph_context = ""
    if entities:
        articles = load_news_from_db(days=days, is_analyzed=True, unit_id=unit_id)
        if articles:
            G = build_entity_graph(articles)
            graph_context = get_graph_context(entities, G)

    # Step 4: 그래프 컨텍스트가 있으면 답변 강화
    if graph_context and rag_result.get('answer'):
        enhanced_answer = (
            f"{rag_result['answer']}\n\n"
            f"**엔티티 관계 분석**:\n{graph_context}"
        )
        rag_result['answer'] = enhanced_answer

    rag_result['graph_context'] = graph_context
    rag_result['entities_found'] = entities
    return rag_result
```

## Phase 2: LangGraph 전환

### 목표

`auto_intel_report.py`의 순수 Python 상태 기계를 **실제 LangGraph 그래프**로 전환.  
목적: 라이브러리 표준 준수 + 향후 conditional edge / 체크포인팅 기반 확보.

### 주의: 의존성 충돌 선행 검증 (필수)

LangGraph는 `langchain-core` + pydantic v2 의존성을 끌고 옴.  
Streamlit Cloud 환경에서 충돌 가능성 있음.

```bash
# 로컬에서 먼저 테스트
pip install langgraph --dry-run 2>&1 | grep -i "conflict\|ERROR"
```

충돌 없으면 진행. 충돌이면 `requirements.txt` 버전 핀닝으로 해결 후 진행.

### 현재 vs 목표 구조

```python
# 현재 (auto_intel_report.py) — 순수 Python 상태 기계
def run_auto_intel_report(period='weekly', skip_email=False, progress_cb=None):
    state = make_state(period=period, progress_cb=progress_cb)
    state = node_load_data(state)
    state = node_detect_surges(state)
    if not state['surges']:
        return state
    state = node_rag_retrieve(state)
    state = node_gen_narrative(state)
    state = node_build_report(state)
    state = node_append_to_doc(state)
    if not skip_email:
        state = node_send_report(state)
    return state

# 목표 (LangGraph) — add_node() 등록
from langgraph.graph import StateGraph, END
from typing import TypedDict, List, Dict, Any

class IntelState(TypedDict):
    period: str
    days: int
    news_current: List[Dict]
    news_prev: List[Dict]
    surges: List[Dict]
    rag_context: Dict
    surge_narrative: str
    analysis_result: Dict
    doc_url: str
    doc_id: str
    report_title: str
    email_sent: bool
    log: List[str]
    errors: List[str]
    skip_email: bool

def build_intel_graph(skip_email: bool = False) -> StateGraph:
    graph = StateGraph(IntelState)

    # 기존 node_* 함수들 그대로 등록
    graph.add_node("load_data",      node_load_data)
    graph.add_node("detect_surges",  node_detect_surges)
    graph.add_node("rag_retrieve",   node_rag_retrieve)
    graph.add_node("gen_narrative",  node_gen_narrative)
    graph.add_node("build_report",   node_build_report)
    graph.add_node("append_to_doc",  node_append_to_doc)
    graph.add_node("send_report",    node_send_report)

    # 엣지 설정
    graph.set_entry_point("load_data")
    graph.add_edge("load_data", "detect_surges")

    # 조건부 엣지: 급등 엔티티 없으면 바로 END
    def surge_router(state: IntelState):
        return "rag_retrieve" if state['surges'] else END

    graph.add_conditional_edges("detect_surges", surge_router)
    graph.add_edge("rag_retrieve",  "gen_narrative")
    graph.add_edge("gen_narrative", "build_report")
    graph.add_edge("build_report",  "append_to_doc")

    if skip_email:
        graph.add_edge("append_to_doc", END)
    else:
        graph.add_edge("append_to_doc", "send_report")
        graph.add_edge("send_report",   END)

    return graph.compile()
```

### `IntelState` TypedDict 정의 포인트

현재 `make_state()` 반환 딕셔너리 (확인된 키 전체):

```python
# auto_intel_report.py make_state() 현재 반환값
{
    'period': str,             # 'weekly' | 'monthly'
    'days': int,               # 7 | 30
    'news_current': List[Dict], # 주의: collected_at은 datetime 또는 str 혼재
    'news_prev': List[Dict],
    'surges': List[Dict],
    'rag_context': Dict,       # {entity_name: {'answer': str, 'sources': list}}
    'surge_narrative': str,
    'analysis_result': Dict,
    'doc_url': Optional[str],
    'doc_id': Optional[str],
    'report_title': str,
    'email_sent': bool,
    'log': List[str],
    'errors': List[str],
    '_progress_cb': Callable,  # ← JSON 직렬화 불가, TypedDict 제외 대상
}
```

**`_progress_cb` 처리**: LangGraph State에서 제외, 단순히 `run_auto_intel_report()` 호출 시 모듈 수준 변수로 유지:

```python
# auto_intel_report.py — 싱글톤 콜백 (단일 사용자, 동시 실행 없음)
_CURRENT_PROGRESS_CB: Callable = lambda msg: None

def _log(state: IntelState, msg: str):
    state['log'].append(msg)
    _CURRENT_PROGRESS_CB(msg)
    log_info(msg)
```

**단일 사용자 가정**: Streamlit 세션은 1명이 동시에 리포트를 실행하지 않으므로 글로벌 콜백으로 충분.

**State 직렬화 주의**: `news_current`의 `collected_at` 필드는 `datetime` 객체일 수 있음. LangGraph 체크포인팅 활성화 전 ISO8601 문자열 변환 필요. 이번 1차 구현에서는 인메모리 실행만 (체크포인팅 비활성), 직렬화 오류 없음.

"""
import json
import sys
import asyncio
from typing import Any, Dict

# mcp 패키지: pip install mcp
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp import types

# 시스템 모듈
from news_engine import (
    get_db_statistics,
    load_news_from_db,
    run_daily_collection,
    log_info,
)
from graph_rag import answer_with_graph_rag   # Phase 1 결과물
from auto_intel_report import run_auto_intel_report
from knowledge_graph import build_entity_graph, detect_surge_entities


app = Server("ironage-ai-analytics")


@app.list_tools()
async def list_tools() -> list[types.Tool]:
    return [
        types.Tool(
            name="search_news",
            description="자연어 질문으로 ICT/통신 뉴스를 GraphRAG 검색합니다.",
            inputSchema={
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "검색할 질문"},
                    "days":  {"type": "integer", "default": 30, "description": "조회 기간 (일)"},
                },
                "required": ["query"]
            }
        ),
        types.Tool(
            name="get_db_stats",
            description="뉴스 DB 현황(기사 수, 최근 수집일)을 조회합니다.",
            inputSchema={"type": "object", "properties": {}}
        ),
        types.Tool(
            name="get_recent_articles",
            description="최근 N일간 수집된 기사 목록을 반환합니다.",
            inputSchema={
                "type": "object",
                "properties": {
                    "days": {"type": "integer", "default": 3},
                    "analyzed_only": {"type": "boolean", "default": False},
                },
            }
        ),
        types.Tool(
            name="get_surge_entities",
            description="이전 기간 대비 급등한 엔티티(기업·기술·국가) 목록을 반환합니다.",
            inputSchema={
                "type": "object",
                "properties": {
                    "days": {"type": "integer", "default": 7},
                }
            }
        ),
        types.Tool(
            name="run_daily_collection",
            description="일일 뉴스 수집을 즉시 실행합니다. (시간 소요: 5-10분)",
            inputSchema={"type": "object", "properties": {}}
        ),
        types.Tool(
            name="run_intel_report",
            description="자율 인텔리전스 리포트를 생성합니다. (시간 소요: 10-20분)",
            inputSchema={
                "type": "object",
                "properties": {
                    "period": {"type": "string", "enum": ["weekly", "monthly"], "default": "weekly"},
                    "skip_email": {"type": "boolean", "default": True},
                }
            }
        ),
    ]


@app.call_tool()
async def call_tool(name: str, arguments: Dict[str, Any]):
    log_info(f"[MCP] 툴 호출: {name}, 인자: {arguments}")

    if name == "search_news":
        result = answer_with_graph_rag(
            query=arguments["query"],
            days=arguments.get("days", 30),
        )
        return [types.TextContent(type="text", text=json.dumps(result, ensure_ascii=False, indent=2))]

    elif name == "get_db_stats":
        stats = get_db_statistics()
        return [types.TextContent(type="text", text=json.dumps(stats, ensure_ascii=False, indent=2))]

    elif name == "get_recent_articles":
        days = arguments.get("days", 3)
        analyzed = arguments.get("analyzed_only", False)
        articles = load_news_from_db(days=days, is_analyzed=True if analyzed else None)
        # MCP 응답은 간결하게: 제목·출처·날짜만
        summary = [{"title": a["title"], "source": a["source"], "published": a["published"]} for a in articles[:20]]
        return [types.TextContent(type="text", text=json.dumps(summary, ensure_ascii=False, indent=2))]

    elif name == "get_surge_entities":
        days = arguments.get("days", 7)
        articles_cur = load_news_from_db(days=days, is_analyzed=True)
        articles_prev = load_news_from_db(days=days * 2, is_analyzed=True)
        G = build_entity_graph(articles_cur)
        surges = detect_surge_entities(articles_cur, articles_prev)
        return [types.TextContent(type="text", text=json.dumps(surges, ensure_ascii=False, indent=2))]

    elif name == "run_daily_collection":
        # 경고: 5-10분 소요 — MCP 30초 타임아웃 초과 가능. 완료 전 응답 없을 수 있음.
        run_daily_collection()
        return [types.TextContent(type="text", text="일일 뉴스 수집 완료")]

    elif name == "run_intel_report":
        period = arguments.get("period", "weekly")
        skip_email = arguments.get("skip_email", True)
        # 경고: 10-20분 소요 — MCP 30초 타임아웃 초과 가능. 완료 전 응답 없을 수 있음.
        state = run_auto_intel_report(period=period, skip_email=skip_email)
        summary = {
            "surge_count": len(state.get("surges", [])),
            "doc_url": state.get("doc_url"),
            "email_sent": state.get("email_sent"),
            "errors": state.get("errors", []),
        }
        return [types.TextContent(type="text", text=json.dumps(summary, ensure_ascii=False, indent=2))]

    else:
        return [types.TextContent(type="text", text=f"오류: 알 수 없는 툴 '{name}'")]


async def main():
    async with stdio_server() as streams:
        await app.run(*streams, app.create_initialization_options())


if __name__ == "__main__":
    asyncio.run(main())

### 성공 기준

- Claude Desktop에서 "오늘 5G 뉴스 동향 알려줘" → `search_news` 툴 실행 → 답변 반환
- `get_db_stats` 툴 → 현재 DB 기사 수 정확히 반환
- `run_intel_report(skip_email=True)` → 에러 없이 리포트 생성 완료
- 툴 실행 오류 시 에러 메시지 반환 (Claude Desktop이 뻗지 않음)

### MCP 서버 배포 모델 (명확화)

**MCP 서버는 로컬 개발자 PC에서 실행 전용.** Streamlit Cloud에는 배포하지 않음.

```
개발자 PC:
  - python mcp_server.py  (백그라운드 또는 터미널)
  - Claude Desktop → stdio 연결 → IRONAGE 툴 사용

Streamlit Cloud:
  - 웹 대시보드 (기존 그대로)
  - MCP 서버 없음
```

### 긴 작업 타임아웃 처리

`run_daily_collection`(5-10분), `run_intel_report`(10-20분)은 MCP 기본 타임아웃(30초) 초과.  
**1차 범위**: 두 툴을 MCP 목록에는 포함하되, 설명에 "오래 걸리는 작업, 완료 전 응답 없을 수 있음" 명시.  
**2차 개선**: 작업 ID 반환 + `get_task_status(task_id)` 폴링 툴 추가 (이번 범위 외).

### Phase 3 주의사항

- MCP 서버는 stdio 기반 → `print()` 사용 금지, 모든 출력은 `log_info()`로만
- `call_tool()` 전체를 `try/except`로 감싸 오류 시 에러 텍스트 반환 (Claude Desktop 프로세스 보호)
- `run_daily_collection`, `run_intel_report` 실행 전 경고 메시지를 첫 번째 `TextContent`로 즉시 반환 검토

## 오픈 질문

1. **MCP 서버 긴 작업 처리**: `run_daily_collection`(5-10분), `run_intel_report`(10-20분)은 MCP 기본 타임아웃 초과 가능. 비동기 실행 + 작업 ID 반환 방식 vs. 타임아웃 연장 중 선택 필요.
2. **LangGraph State 체크포인팅**: 나중에 `MemorySaver` 도입 시 SQLite 체크포인터로 자동 재시작 가능. 이번 1차 구현에서는 메모리 체크포인터만 사용.
3. **GraphRAG 그래프 캐싱 전략**: `build_entity_graph()`가 기사 수에 따라 1-5초 소요. Streamlit `@st.cache_data(ttl=3600)`로 1시간 캐시 또는 일 1회 사전 빌드 중 선택.
