# 05. 부서별 맞춤 설정 가이드

**대상**: 배포를 완료한 담당자  
**목적**: 우리 부서의 관심 분야에 맞게 키워드·이메일·팀 구조를 커스터마이즈

---

## 기본 원칙

`data/config.json` 파일 하나로 대부분의 동작을 제어합니다.  
코딩 없이 텍스트 편집만으로 부서별 맞춤 설정이 가능합니다.

```
config.json 수정 항목
├── 검색 키워드 (naver_queries)
├── Google Alerts RSS URL (google_alerts_rss)
├── 이메일 수신자 (gmail_receivers)
├── AI 분석 모델 (ai_model)
└── 모니터링 기관 RSS (standards_org_rss)
```

---

## 1. 모니터링 키워드 설정

`naver_queries`에 우리 부서가 모니터링해야 할 핵심 키워드를 입력합니다.

```json
"naver_queries": [
    "키워드1", "키워드2", ...
]
```

### TTA 조직별 키워드 예시

#### 미래전략기획실

```json
"naver_queries": [
    "ICT 정책", "디지털 규제", "AI 규제",
    "표준화 전략", "국제 협력", "ITU",
    "스마트국가", "데이터경제", "디지털뉴딜",
    "TTA 표준", "OECD 디지털"
]
```

#### AI통신융합연구소

```json
"naver_queries": [
    "5G 표준", "6G 연구", "오픈랜 O-RAN",
    "위성통신", "양자통신", "비지상통신망 NTN",
    "네트워크 슬라이싱", "엣지컴퓨팅",
    "AI 통신", "3GPP 표준"
]
```

#### AI기반기술연구소

```json
"naver_queries": [
    "생성형 AI", "대규모언어모델 LLM", "AI 안전성",
    "AI 신뢰성", "AI 표준화", "AI 평가",
    "딥러닝", "멀티모달", "AI 거버넌스",
    "ISO AI 표준", "ITU-T AI"
]
```

#### AX/SW연구소

```json
"naver_queries": [
    "디지털전환 DX", "클라우드 표준", "SaaS",
    "SW 품질", "SW 안전성", "DevOps",
    "마이크로서비스", "컨테이너", "쿠버네티스",
    "SW 인증", "오픈소스"
]
```

#### 정보보호안전연구소

```json
"naver_queries": [
    "사이버보안", "랜섬웨어", "제로트러스트",
    "개인정보보호", "ISMS", "CC인증",
    "취약점", "사이버 위협", "인증체계",
    "정보보호법", "KISA"

```

**권장 설정**
- 키워드 10~20개 적당 (너무 많으면 수집량 과다, 관련 없는 기사 증가)
- 2~4단어 구절이 단어 하나보다 정확도 높음 ("AI" 보다 "AI 표준화")
- 매 분기 리뷰하여 최신 이슈 키워드로 업데이트 권장

## 2. Google Alerts RSS 설정

국제 영문 뉴스까지 포함하려면 Google Alerts를 추가합니다.

```json
"google_alerts_rss": [
    "https://www.google.co.kr/alerts/feeds/...",
    "https://www.google.co.kr/alerts/feeds/..."
]
```

### Google Alerts RSS 만들기

1. https://www.google.co.kr/alerts 접속
2. 검색창에 키워드 입력 (예: `6G standardization`)
3. 옵션 설정:
   - 빈도: `실시간`
   - 소스: `뉴스`
   - 언어: `모든 언어` (국제 뉴스 포함)
   - 전송 대상: **RSS 피드**
4. 알림 만들기 → RSS 아이콘 클릭 → URL 복사 → 배열에 추가

## 4. 표준화 기관 RSS 설정

TTA 조직별 관련 국제기구 공식 RSS를 추가합니다.

```json
"standards_org_rss": [
    "https://www.itu.int/rss/updates.xml"
]
```

| 조직 | 주요 모니터링 국제기구 |
|------|--------------------|
| 미래전략기획실 | ITU, OECD, WTO(전기통신) |
| 표준화본부 | ITU-T, ITU-R, 3GPP, IEEE |
| AI통신융합연구소 | 3GPP, ETSI, IEEE 802 |
| AI기반기술연구소 | ITU-T SG13, ISO/IEC JTC1/SC42 |
| AX/SW연구소 | ISO/IEC JTC1/SC7, ETSI |
| 정보보호안전연구소 | ITU-T SG17, ISO/IEC JTC1/SC27, IETF |

## 5. 팀(단) 구조 설정

### 현재 표준화본부 구조

현재 시스템은 표준화본부의 4개 단 구조로 운영됩니다:
- 표준기획단
- 표준혁신단
- AI융합표준단
- 전파네트워크표준단

### 다른 조직에서 활용할 때

4개 단 구조는 **팀 또는 업무 분야**로 자유롭게 바꿀 수 있습니다.

#### 방법 1: 웹 대시보드에서 직접 편집 (권장)

1. 대시보드 실행: `streamlit run main_app.py`
2. 좌측 메뉴 → **⚙️ 단별 설정** 클릭 (관리자 로그인 필요)
3. 각 단의 이름, 키워드, RSS, 이메일 수신자를 직접 편집
4. **저장** 버튼 클릭

#### 방법 2: 단 수 조정 예시

| 조직 | 단 구성 예시 |
|------|-----------|
| AI통신융합연구소 | 5G연구팀 / 6G연구팀 / 위성통신팀 / AI융합팀 |
| 정보보호안전연구소 | 사이버보안팀 / 개인정보보호팀 / 인증평가팀 |
| AX/SW연구소 | DX연구팀 / SW품질팀 / 클라우드팀 |

## 6. @tta.or.kr 계정과 Google Drive 연동

> **중요**: 이 섹션은 TTA 임직원 모두에게 해당하는 주의 사항입니다.

### 문제 상황

TTA 임직원의 업무 이메일(`이름@tta.or.kr`)은 Google Workspace(기업용 구글) 계정입니다.  
그러나 이 시스템의 Google Drive·Docs 연동 인증은 **Google의 OAuth2 앱 등록** 과정을 통해 이루어지며,  
외부 앱으로 등록된 경우 **조직 관리자(TTA IT 담당)가 앱 접근을 허용**해야 합니다.

TTA IT 부서에서 외부 앱 접근을 별도로 허용하지 않은 경우,  
`@tta.or.kr` 계정으로는 인증 화면에서 차단될 수 있습니다.

### 해결 방법: 개인 Gmail 계정으로 인증

가장 간단하고 확실한 방법은 **개인 Gmail 계정**(`이름@gmail.com`)으로 OAuth2 인증을 진행하는 것입니다.

```
시스템 인증용 (개인 Gmail 사용)
  credentials.json + token.json → 개인 Gmail(@gmail.com) 계정으로 인증

보고서 공유 방법
  생성된 Google Docs를 @tta.or.kr 이메일로 공유
  → Google Drive 링크를 이메일로 발송
  → @tta.or.kr 수신자가 링크 클릭 → 문서 열람
```

### 단계별 설정 방법

**1단계**: 개인 Gmail 계정으로 Google Cloud Console 프로젝트 생성  
→ 02_API키_발급_상세가이드.md의 'Google OAuth2 인증 설정' 참조  
→ 이때 개인 Gmail 주소로 로그인

**2단계**: OAuth2 동의 화면에서 테스트 사용자 추가  
→ 개인 Gmail 주소 추가  
→ 필요시 `이름@tta.or.kr`도 추가 시도 (허용되면 사용 가능)

**3단계**: 인증 실행  
```bash
python news_engine.py test
```
→ 브라우저에서 개인 Gmail 계정 선택 → 권한 허용  
→ `token.json` 자동 생성

**4단계**: 보고서를 팀원들과 공유  
→ `data/config.json`의 `gmail_receivers`에 `@tta.or.kr` 주소 입력  
→ 이메일 본문의 Google Docs 링크를 팀원이 클릭하면 열람 가능

> **요약**: 인증(인프라)은 개인 Gmail로, 보고서 수신·열람은 @tta.or.kr 업무 메일로 운영합니다.

## 7. AI 분석 모델 선택

```json
"ai_model": "gpt-4o"
```

| 설정값 | 모델 | 특징 | 비용 |
|--------|------|------|------|
| `"gpt-4o"` | OpenAI GPT-4o | 가장 정확, 속도 빠름 | 중간 |
| `"claude-sonnet-4-6"` | Anthropic Claude | 긴 문서 분석 강점 | 중간 |
| `"gemini-2.5-flash"` | Google Gemini | 빠르고 저렴 | 낮음 |

## 8. 설정 변경 후 반영
