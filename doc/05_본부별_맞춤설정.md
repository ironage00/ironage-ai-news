# 05. 본부별 맞춤 설정 가이드

**대상**: 배포를 완료한 담당자  
**목적**: 우리 본부의 관심 분야에 맞게 키워드·이메일·단 구조를 커스터마이즈

---

## 기본 원칙

이 시스템은 `data/config.json` 파일 하나로 대부분의 동작을 제어합니다.  
코딩 없이 텍스트 편집만으로 본부별 맞춤 설정이 가능합니다.

```
config.json 수정 항목
├── 검색 키워드 (naver_queries)
├── Google Alerts RSS URL (google_alerts_rss)
├── 이메일 수신자 (gmail_receivers)
├── AI 분석 모델 (ai_model)
└── 모니터링 기관 RSS (standards_org_rss)
```

---

## 1. 모니터링 키워드 설정

### naver_queries — 네이버 뉴스 검색어

우리 본부가 모니터링해야 할 핵심 키워드 목록입니다.

```json
"naver_queries": [
    "키워드1", "키워드2", ...
]
```

#### 본부별 키워드 예시

**융합기술본부**
```json
"naver_queries": [
    "인공지능", "AI 표준", "머신러닝", "딥러닝",
    "빅데이터", "데이터 표준", "클라우드 컴퓨팅",
    "IoT 표준", "엣지컴퓨팅", "디지털트윈",
    "메타버스", "XR 표준", "블록체인"
]
```

**정보통신미디어본부**
```json
"naver_queries": [
    "OTT 규제", "디지털미디어", "방송통신 표준",
    "콘텐츠 플랫폼", "미디어 법안", "스트리밍",
    "디지털방송", "UHD 표준", "HDR"
]
```

**사이버보안본부**
```json
"naver_queries": [
    "사이버보안", "랜섬웨어", "제로트러스트",
    "암호화", "인증 표준", "취약점", "해킹",
    "개인정보보호", "ISMS", "CC인증"
]
```

**스마트교통물류본부**
```json
"naver_queries": [
    "자율주행", "C-ITS", "V2X",
    "스마트물류", "드론 배송", "자율주행차",
    "교통 표준", "철도 통신", "스마트도로"
]
```

**바이오헬스본부**
```json
"naver_queries": [
    "디지털헬스", "의료기기 표준", "원격진료",
    "PHR", "의료 AI", "스마트병원",
    "헬스케어 데이터", "의료정보 표준"
]
```

#### 권장 설정
- 키워드는 **10~20개** 적당 (너무 많으면 수집량 과다)
- **2~4단어 구절**이 단어 하나보다 정확도 높음
  - "AI" 보다 "AI 표준화" 가 더 정확한 결과
- 매 분기 리뷰하여 최신 이슈 키워드로 업데이트 권장

## 2. Google Alerts RSS 설정

### google_alerts_rss — 구글 알림 RSS 피드

국제 영문 뉴스까지 포함하려면 Google Alerts를 활용합니다.

```json
"google_alerts_rss": [
    "https://www.google.co.kr/alerts/feeds/...",
    "https://www.google.co.kr/alerts/feeds/..."
]
```

#### Google Alerts RSS 만들기 (반복 절차)

각 핵심 키워드마다 별도 알림을 만드는 것을 권장합니다:

1. https://www.google.co.kr/alerts
2. 검색창에 키워드 입력 (예: `6G standardization`)
3. 옵션 설정:
   - 빈도: `실시간`
   - 소스: `뉴스`
   - 언어: `모든 언어` (국제 뉴스 포함)
   - 지역: `모든 지역`
   - 전송 대상: **RSS 피드**
4. 알림 만들기 → RSS 아이콘 클릭 → URL 복사 → 배열에 추가

#### 권장 알림 수: 10~30개

국내 키워드는 네이버로, 국제 키워드는 Google Alerts로 이중 커버합니다.

## 4. 표준화 기관 RSS 설정

### standards_org_rss — ITU·ISO·3GPP 등 국제기구 공식 발표

```json
"standards_org_rss": [
    "https://www.itu.int/rss/...",
    "https://www.iso.org/rss/..."
]
```

본부별 관련 표준화 기관:

| 본부 | 주요 기관 |
|------|---------|
| 이동통신 | ITU-R, 3GPP, IEEE 802 |
| AI/데이터 | ITU-T SG13, ISO/IEC JTC1/SC42 |
| 보안 | ITU-T SG17, ISO/IEC JTC1/SC27, IETF |
| 방송미디어 | ITU-R SG6, ETSI, DVB |
| 교통 | ISO TC204, IEEE 1609 |

## 5. AI 분석 모델 선택

```json
"ai_model": "gpt-4o"
```

| 설정값 | 모델 | 특징 | 비용 |
|--------|------|------|------|
| `"gpt-4o"` | OpenAI GPT-4o | 가장 정확, 속도 빠름 | 중간 |
| `"claude-sonnet-4-6"` | Anthropic Claude | 긴 문서 분석 강점 | 중간 |
| `"gemini-2.5-flash"` | Google Gemini | 빠르고 저렴 | 낮음 |

## 6. 단(Unit) 구조 설정

### 단이란?

이동통신표준팀은 내부적으로 4개 단으로 구성되어 있습니다:
- 표준기획단
- 표준혁신단
- AI융합표준단
- 전파네트워크표준단

다른 본부에서는 이 구조를 **팀 또는 업무 분야**로 대체할 수 있습니다.

### 단 구조 변경 방법

웹 대시보드에서 직접 편집 가능합니다:

1. 대시보드 실행: `streamlit run main_app.py`
2. 좌측 메뉴 → **⚙️ 단별 설정** 클릭
3. 각 단의 이름, 키워드, 이메일 수신자를 직접 편집
4. **저장** 버튼 클릭

또는 DB를 직접 수정:

```python
# 단 구조 커스터마이즈 예시 (Python)
# news_engine.py의 DEFAULT_UNITS 상수를 수정

DEFAULT_UNITS = [
    {
        "unit_id": "unit_1",
        "unit_name": "AI정책팀",
        "keywords": ["AI 정책", "AI 규제", "인공지능법"],
        "email_receivers": ["ai-policy@org.kr"]
    },
    {
        "unit_id": "unit_2",
        "unit_name": "데이터표준팀",
        "keywords": ["데이터 표준", "데이터 거버넌스"],
        "email_receivers": ["data-std@org.kr"]
    }
]
```

## 7. 알림 임계값 설정

급등 키워드가 얼마나 증가해야 알림을 보낼지 설정합니다.

```json
"alert_impact_level": 3
```

| 값 | 의미 | 알림 빈도 |
|----|------|---------|
| 1 | 20% 이상 증가 시 알림 | 매우 자주 |
| 2 | 50% 이상 증가 시 알림 | 자주 |
| 3 | 100% 이상 증가 시 알림 (기본값) | 적당함 |
| 4 | 200% 이상 증가 시 알림 | 가끔 |
| 5 | 500% 이상 증가 시 알림 | 중요 이슈만 |

## 8. 설정 변경 후 반영 방법

### 로컬 환경 (즉시 반영)

`data/config.json`을 수정하면 다음 실행부터 자동 반영됩니다.  
서버 재시작 불필요.

### GitHub Actions (클라우드 자동화)

`data/config.json`은 GitHub에 올라가지 않습니다 (보안).  
키워드처럼 민감하지 않은 설정을 GitHub에도 반영하려면:

1. `data/config.json`에서 민감 정보(API 키)를 제거한 버전을 `data/config.example.json`으로 저장
2. `news_engine.py`에서 환경 변수로 민감 정보 받도록 설정되어 있으므로 
   GitHub Secrets에 값이 있으면 config.json의 값을 자동으로 오버라이드합니다.

## 9. 수집 빈도 조정

기본값은 매일 1회(09:00 KST)입니다.  
필요에 따라 cron-job.org에서 스케줄을 변경합니다.

| 빈도 | cron 표현식 (UTC 기준) | 설명 |
|------|---------------------|------|
| 매일 09:00 KST | `0 0 * * *` | 기본값 |
| 매일 2회 (09:00, 18:00 KST) | `0 0,9 * * *` | 오전/오후 수집 |
| 평일만 09:00 KST | `0 0 * * 1-5` | 주말 제외 |
| 매일 06:00 KST | `0 21 * * *` | 더 이른 시간 |

> UTC와 KST의 차이: KST = UTC + 9시간  
> KST 09:00 = UTC 00:00

## 맞춤 설정 체크리스트

```
[ ] naver_queries: 본부 관심 키워드 10~20개로 교체

[ ] gmail_receivers: 실제 수신자 이메일 목록으로 교체

[ ] 변경 후 테스트 실행: python news_engine.py daily
```
