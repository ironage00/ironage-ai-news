## 자주 발생하는 문제와 해결책

### 문제 1: 이메일이 오지 않는다

**확인 순서**:

1. **GitHub Actions 성공 여부 확인**
   - Actions 탭 → 오늘 날짜 실행 항목 → 결과 확인
   - 실패했다면 로그 클릭 → 오류 메시지 확인

2. **스팸 메일함 확인**
   - Gmail의 경우 자동 발송 이메일이 스팸으로 분류될 수 있음
   - 스팸함에서 발견되면 "스팸 아님" 처리

3. **Gmail 앱 비밀번호 만료 확인**
   - Google 보안 설정에서 앱 비밀번호 재발급
   - GitHub Secrets의 `GMAIL_PASSWORD` 업데이트

4. **수집된 기사가 0건인 경우**
   - Actions 로그에서 수집 결과 확인
   - 네이버 API 할당량 초과 여부 확인 (일 25,000건 무료)

---

### 문제 2: GitHub Actions가 실패한다

Actions 로그에서 오류 메시지를 확인합니다.

**주요 오류 유형별 해결**:

#### `Error: No DATABASE_URL`
```
원인: GitHub Secrets에 DATABASE_URL이 없거나 잘못됨
해결: Settings → Secrets → DATABASE_URL 값 재확인
     Supabase 프로젝트가 일시 중지 상태인지 확인
```

#### `OpenAI API error: insufficient_quota`
```
원인: OpenAI 크레딧 소진
해결: https://platform.openai.com/billing 에서 크레딧 충전
```

#### `Authentication error: Google`
```
원인: token.json 만료 또는 GOOGLE_TOKEN_JSON Secret 오류
해결:
  1. 로컬에서 python news_engine.py test 실행 → 재인증
  2. 새로 생성된 token.json 내용을 복사
  3. GitHub Secrets의 GOOGLE_TOKEN_JSON 값 교체
```

#### `Connection refused: Supabase`
```
원인: Supabase 무료 플랜 일시 정지 (7일 미접속 시 자동 정지)
해결:
  1. https://supabase.com → 프로젝트 접속
  2. "Resume project" 버튼 클릭
  3. 재시작 완료 후 Actions 재실행
```

#### `Rate limit: Naver API`
```
원인: 네이버 API 일일 호출 한도 초과
해결:
  1. 다음 날 자동 초기화됨 (즉시 해결 불필요)
  2. 장기적으로: naver_queries 수를 줄이거나
     google_alerts_rss 비중을 높임
```

### 문제 4: 수집되는 뉴스가 관련 없는 기사가 많다

```
해결:
1. data/config.json의 naver_queries 키워드를 더 구체적으로 변경
   예: "AI" → "AI 표준화", "인공지능 정책"
2. Google Alerts를 더 구체적인 검색어로 설정
3. config.json의 ict_min_articles 값을 높여 필터링 강화
```

---

### 문제 5: Supabase DB 용량 부족 (무료 500MB 초과)

```
해결 방법 (중 하나 선택):

방법 A: 오래된 기사 정기 삭제
  - 대시보드 → 관리자 탭 → 기사 정리 실행
  - 또는 3개월 이상 된 기사 자동 삭제 스케줄 설정

방법 B: Supabase 유료 플랜 업그레이드
  - Pro 플랜: $25/월, 8GB
  - 연간 약 30만원

방법 C: SQLite 로컬 모드로 전환
  - .env에서 DATABASE_URL을 제거하면 로컬 SQLite 사용
  - 단, 클라우드 자동화가 DB를 공유하지 못함
```

## Supabase DB 직접 확인 방법

수집 현황을 직접 DB에서 확인하고 싶을 때:

1. https://supabase.com → 프로젝트 클릭
2. 좌측 **Table Editor** 클릭
3. `news_articles` 테이블 선택
4. 전체 데이터 확인 가능

또는 SQL 쿼리 실행:
1. 좌측 **SQL Editor** 클릭
2. 아래 쿼리 입력:

```sql
-- 오늘 수집 기사 수
SELECT COUNT(*) FROM news_articles
WHERE collected_at >= CURRENT_DATE;

-- 단별 분석 현황
SELECT unit_id, COUNT(*) as total
FROM news_articles
WHERE is_analyzed = true
GROUP BY unit_id;

-- 최신 기사 10건
SELECT title, source, collected_at
FROM news_articles
ORDER BY collected_at DESC
LIMIT 10;
```

## API 비용 모니터링

### OpenAI 사용량 확인

1. https://platform.openai.com/usage 접속
2. 월별 사용량 및 비용 확인
3. 한도 설정 권장:

## 자주 묻는 질문 (FAQ)

**Q. 주말에도 뉴스가 수집되나요?**  
A. 네, 기본 설정은 매일 실행됩니다. 평일만 원하면 cron 표현식을 `0 0 * * 1-5`로 변경.

**Q. 이메일을 추가/제거하려면?**  
A. `data/config.json`의 `gmail_receivers` 배열을 수정하세요.

**Q. 특정 기사를 다시 분석하려면?**  
A. 웹 대시보드 → 뉴스 현황 → 해당 기사 → 재분석 버튼 클릭.

**Q. 리포트를 즉시 받고 싶어요.**  
A. GitHub Actions 탭 → Daily News Collection → Run workflow.  
또는 로컬에서 `python news_engine.py daily` 실행.

**Q. Google Docs 보고서가 어디에 저장되나요?**  
A. 업무용 Gmail 계정의 Google Drive → `99_일일동향` 폴더 → 단별 하위 폴더.

**Q. OpenAI API 없이도 쓸 수 있나요?**  
A. Claude나 Gemini 키로 대체 가능합니다. `ai_model` 설정을 변경하세요.

**Q. 로컬 PC를 꺼도 시스템이 돌아가나요?**  
A. 네. 클라우드(GitHub Actions + Supabase)에서 모두 실행됩니다.  
로컬 PC는 설정 변경이나 대시보드 확인 시에만 켜면 됩니다.

**Q. 무료로 계속 쓸 수 있나요?**  
A. OpenAI API 비용 외에는 무료입니다. OpenAI 비용은 월 5,000~15,000원 수준입니다.
