## 진단: 6개 공백 영역

### Gap 1 — 이상 신호(Weak Signal) 섹션 없음 [🔴 고우선순위]

- 현재: 모든 이슈가 기사 빈도 기준으로 선택됨 (많이 나온 것 = 중요한 것)
- 문제: 이번 주 처음 등장했지만 잠재 임팩트가 큰 저빈도 기사가 묻힘
- 벤치마크: 국가정보원 산업보안 동향은 "이상 징후" 섹션을 별도 운영
- **영향 범위**: `trend_analyzer.py` 프롬프트 + JSON 스키마

### Gap 2 — 정량적 외부 신호 부재 [🔴 고우선순위]

- 현재 통계: 기사 수, 분석 완료 수, 평균 품질 점수 → 시스템 내부 지표
- 문제: 보직자에게 필요한 것은 시장 신호 (키워드 급등률, 신규 플레이어 등장 수 등)
- 벤치마크: Bloomberg Briefing은 정량 수치 중심 오프닝
- **영향 범위**: `trend_analyzer.py` 통계 섹션 + `generate_statistics_data()` 함수

### Gap 3 — 경쟁 구도·주도국 식별 없음 [🟡 중우선순위]

- 현재: "5G 투자 확대" 같은 이슈 기술 시 "누가 앞서는가"가 없음
- 문제: 표준화 레이스에서 한국/TTA 포지션 판단 불가
- 벤치마크: McKinsey는 이슈마다 "주도 행위자(Leading Actor)" 명시
- **영향 범위**: `trend_analyzer.py` 핵심 이슈 프롬프트 스키마

### Gap 4 — 의사결정 타임라인 없음 [🟡 중우선순위]

- 현재: `tta_action_item` 한 줄로 대응 방향만 제시
- 문제: "즉시 검토", "3개월 내", "연간 계획 반영" 구분이 없어 보직자가 우선순위 판단 불가
- 벤치마크: McKinsey Executive Briefing의 "Decision Gate" 개념
- **영향 범위**: `trend_analyzer.py` 핵심 이슈 JSON 스키마

### Gap 5 — 이슈 간 인과 연결 없음 [🟡 중우선순위]

- 현재: 이슈들이 독립 항목으로 나열됨
- 문제: "AI 반도체 규제 → 5G 장비 개발 차질 → 표준화 일정 지연" 같은 연쇄 영향 파악 불가
- 벤치마크: ETRI 주간기술동향은 기술 간 상호 영향 서술 포함
- **영향 범위**: `trend_analyzer.py` 월간 프롬프트 (주간은 범위 제한으로 생략 가능)

### Gap 6 — 이메일 제목·오프닝 고정 형식 [🟢 저우선순위]

- 현재: `[TTA] 주간 ICT 트렌드 분석 리포트 (2026년 05월 29일)` — 매주 동일
- 문제: 특이성 없어 개봉률 저하 가능성
- 벤치마크: Bloomberg Briefing은 제목에 이번 주 핵심 이슈 한 줄 삽입
- **영향 범위**: `trend_analyzer.py` `send_trend_report_email()` 제목 생성 로직

## 개선 설계 (구현 상세)

### 개선 A — `weak_signals` 필드 추가 [Gap 1]

**JSON 스키마 추가 필드 (주간·월간 공통):**
```json
"weak_signals": [
  {
    "signal": "이상 신호 제목",
    "description": "ㅇ 왜 주목해야 하는가",
    "potential_impact": "상/중",
    "related_articles": ["기사 제목 1"]
  }
]
```

**프롬프트 지시 추가:**
```
weak_signals: 이번 기간 처음 등장했지만 향후 임팩트가 클 수 있는 저빈도(1~2건) 기사 2~3건 추출.
기사 빈도가 아닌 '기술적 파급력 또는 정책 변화 가능성' 기준으로 선택.
```

**보고서/이메일 표시**: `⚡ 이상 신호` 섹션으로 핵심 이슈 바로 아래에 배치

### 개선 B — 통계 섹션 → 시장 신호 지표로 전환 [Gap 2]

**현재 → 변경:**

| 현재 지표 | 변경 지표 |
|-----------|-----------|
| 전체 기사 수 | 급등 키워드 TOP 3 (전주 대비 +N%) |
| 분석 완료 수 | 신규 등장 플레이어/기업 수 |
| 평균 품질 점수 | 이번 주 신규 이슈 수 vs 연속 이슈 수 |
| 주요 출처 | 주요 출처 (유지) |

**구현 방법**: `generate_statistics_data()` 반환값에 `keyword_surge`, `new_entities`, `new_vs_recurring` 필드 추가.  
기존 내부 지표는 보고서 하단 "분석 메타데이터" 섹션으로 이동 (숨기지는 않음).

**프롬프트 지시 추가:**
```

  - "3개월 내": 다음 분기 계획 반영
  - "연간 계획 반영": 중장기 로드맵 검토
  - "모니터링 유지": 현재 액션 불필요, 추이 관찰
```

## 구현 시 주의사항

1. **AI 프롬프트 토큰 증가**: 스키마 필드 추가로 초안 생성 토큰이 증가함. `max_tokens_initial` 값 조정 필요 (현재 2500 → 3000 권장).

2. **`leading_actor` 환각 리스크**: AI가 존재하지 않는 기업명을 생성할 수 있음. 검증 프롬프트에 "leading_actor는 실제로 언급된 기업·국가명만 기재, 추정 금지" 지시 추가 필요.

3. **`weak_signals` 선택 기준 모호성**: "저빈도 고임팩트" 기준이 AI마다 다를 수 있음. 초기 운영 후 실제 선택 결과 모니터링 필요.

4. **`decision_timeline` 남용 방지**: AI가 모든 이슈를 "즉시 검토"로 분류할 수 있음. 프롬프트에 "즉시 검토는 최대 1~2건만 허용" 제약 추가.

5. **기존 `technology_highlights` 섹션**: Gap 3(경쟁 구도)와 일부 중복됨. 개선 C 적용 시 `technology_highlights`와 역할 분리 명확화 필요.
